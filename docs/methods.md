# Methods and experiment decisions

## Implemented experiment

One scalar predicate (`release_state`) and values `preliminary`, `published`, `withdrawn`, or explicit null. Exact entity matching; trusted loader annotations for value, authority, effective date and correction authorization. All five action proposals use the same deterministic validator and immutable SQLite transaction path.

Two separate passes answer distinct questions. Gold-history action classification gives each proposer the same correct historical snapshot and evaluates raw five-action macro-F1. Closed-loop replay starts an independent empty ledger and measures its own accumulated state against fixed independently specified checkpoints. A recovery operation in a diverged store is not scored against an incompatible gold-history action label.

State exact match includes value, retraction/absence status, effective boundary and interval end. Provenance is separately scored with source-set precision/recall; mechanical source/span validation is separate from entailment. Stale-active rate uses changed gold checkpoints and explicitly excludes absent selections; missing-state rate is reported beside it. False-overwrite compares semantic state at every existing or proposed effective boundary, including future and historical intervals; provenance-only reinforcement is excluded. It follows the handoff's literal operational definition: semantic changes at gold non-mutating opportunities / all such opportunities. This metric can include recovery from a prior model error; interpret it with state exact match and missing-state rate when model arms are introduced. Deterministic QA checks the same key/time answer and source set; it is not evidence from an independent language-answer task.

Invalid raw proposals count as errors. Original returned payloads are retained before parsing. Parse-invalid and validator-rejection rates are reported separately for gold-history and closed-loop tracks; the combined invalid-output rate counts both passes. Validator denominators count only parsed proposals. Conservative no-op is not silently made correct. Undefined rates use null and denominator zero. Per-trajectory records and every raw request/proposal/commit/checkpoint are saved. Runtime stamps and measured latency can differ across replay; source, dataset and projected-state hashes must reproduce.

## Training gate

**Decision: `training_not_justified` for a research training campaign in this bounded annotated-input MVP.** The first automated pilot matches all 412 operation labels and 1,005 state checkpoints using transparent rules. This is provisional automated evidence: human reviewers = 0. It does not certify independent label quality or imply that arbitrary language memory is solved.

Release A deferred Tasks 5–7 under the design's stop condition. Task 5 then completed the explicitly authorized base-model download and ten-request CPU smoke, which produced zero schema-valid proposals. When the user requested alignment with the original folder 1 brief, the audit confirmed identical source requirements but an over-deferred educational training control. Task 6 now includes two bounded educational LoRA runs with actual saved/reloaded adapters. The default and single allowed accumulation adjustment reached 2/20 and 13/20 exact canonical training targets; neither met the full overfit goal. No full research-training campaign, matched comparison or final holdout access occurred. Human reviewers remain zero. Missing cached runtimes return exit 3 rather than rule substitutes; research training remains disabled. Do not weaken the rule or change test difficulty after seeing results to obtain a model win.

## Educational completion-only training

Fresh synthetic splits were frozen before optimization: 20 training trajectories/163 observations and five development trajectories/44 observations, with disjoint entities/templates. Select the first four eligible targets per action for twenty training records. Inputs use only current observations and legitimate gold-history snapshots; targets are separate canonical JSON completions. Every prefix label is `-100`, completion/EOS labels are supervised, and the masked prefix token IDs must equal inference token IDs exactly. Real sequences contain 787–1,035 tokens; overlength inputs fail before optimization, with packing and truncation disabled.

Rank 16, alpha 32, dropout .05, q/v projections only; CPU float32, seed 11, learning rate .0002, at most three epochs and microbatch one. The default accumulation sixteen yields six optimizer steps. The original brief permits one small development adjustment: accumulation one yields sixty, while corpus/base/initial-adapter hashes and all other settings stay fixed. Both full results are preserved. AdamW uses weight decay zero, gradient clipping one, mean-per-example completion loss and correctly normalized partial accumulation windows. [Model card and measurements](model-card.md).

This smoke saves the final bounded state rather than selecting a research checkpoint. Full base-parameter hashes must remain equal, adapter hashes must change, and two fixed development requests must reproduce exact generated token arrays after a fresh-base reload. Those checks passed for both runs; identity is not a quality score. All twenty training responses, including schema/guard/action/exact-target failures, are retained. No larger campaign or further tuning followed the one adjustment. Independent human review and the full development-selected, matched comparison remain unfinished.

## Optional prompted-model boundary

The [base configuration](../configs/base.json) pins the same Qwen3-0.6B commit for model and tokenizer. One fixed prompt uses declared observation/history fields only, excludes extra gold/future annotations, rejects evidence observed after the current request, and admits at most 16 assertion versions. The actual chat-template token count must fit 2,048 input tokens without truncation. Output is limited to 256 new tokens, with nonthinking, greedy, unconstrained decoding. This is our deterministic comparison default, not Qwen's general decoding recommendation. Malformed/schema-invalid/duplicate-key JSON is rejected without repair; raw text, failures, prompt hashes and token counts remain in saved predictions. Schema-valid fabricated targets or evidence reach the shared guard, which records their rejection without mutation.

Runtime selection is explicit CPU or MPS, float32, with no device or rule fallback. All model/tokenizer reads use local cached files and disable custom remote code. Fake-runtime runs have `model_status=fake_runtime` and `model_runtime_evaluated=false`; native API checks use randomly initialized tiny Qwen3 weights and are not pretrained-model evidence. The [real CPU smoke](../examples/qwen-smoke-cpu/README.md) used ten initial-create pilot requests with empty histories. All responses were valid JSON but failed the required schema, so none reached semantic validation. It separately recorded a passing four-token backward check with no optimizer, weight updates or saved adapter. This establishes basic compatibility only, not training throughput or full LoRA feasibility. [Setup and sources](model-runtime.md).

## Uncertainty and limitations

One development generator seed (11), no human-reviewed labels, no independently written style set, no external benchmark, and no complete model comparison arms. The ten-request model smoke covers initial-create events only. No between-model effect, confidence interval or statistical significance is claimed. Full model experiments would use frozen splits, matched revisions/budgets, seeds 11/22/33 where feasible, and 2,000 paired whole-trajectory bootstrap draws with pooled numerators/denominators. Those experiments have not run.

Resource timings are a single process run on this Mac; process memory can include prior work and warmup is not isolated. They are diagnostic, not serving benchmarks or CUDA evidence. Annotation-determined actions and a tiny predicate vocabulary sharply limit generalization.

## Data integrity gate

Before run artifacts are created, the loader recomputes dataset identity, verifies exact hashes and actual counts, and checks unique observation/gold/group identities, entity/split/template membership, gold joins, checkpoint ownership and knowledge time, provenance availability, duplicate checkpoints, and complete current/earliest/latest boundary coverage for this generator format. An incomplete checkpoint file cannot silently narrow a passing denominator. This validates structural evidence; it does not replace a human label audit.
